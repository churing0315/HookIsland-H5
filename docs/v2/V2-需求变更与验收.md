# 拉钩岛 Demo V2 — 正俯视地图、分期扩建、缩放与素材库升级

**状态：** 开发变更草案（直接来自用户的新增诉求 + 标注为“建议”的可讨论设计决定）
**基线：** 现有 Phaser + TypeScript + Vite H5 原型已经构建、通过至少6条测试、可在网页预览；本轮严格增量修改。

## 2. 需求变更（必须实现）

### V2-01 视角与地块结构
- 岛屿为**正俯视二维平面方格地图**，不是旧版2.5D等距斜视地图；地面水平/垂直方格，不采用菱形透视格。
- 草地、沙滩和岩石扩展均由与草地同规格的网格 tile 拼接，不能把沙滩/岩石绘制成不可编辑的不规则单幅插画。
- 允许地块拼接后的视觉岸边在格子基础上做小圆角/柔化，但必须保留准确网格占地数据。水域不允许建造。
- 建筑与树木绘制为可爱、低细节、圆润的二维卡通 PNG/Sprite；**场景正俯视并不强制建筑只能显示屋顶**：为保持所给参考图风格，可采用微露立面的卡通道具图，但其落脚点与占格严格按正交网格处理。

### V2-02 地图扩建
- 实现 `stage=0/1/2` 三段可复用地图数据，不使用三张整幅截图互换代替真实地块。
- 阶段0参考小岛；阶段1增加草地；阶段2左上追加沙滩格、右下追加岩石格，中心可以摆放大建筑。
- 升级地图时 **不能移动/重置旧建筑、已有存档坐标与铭牌**；新增的只是地块与可放置空间。允许动画显示新地块加入。
- 建议解锁条件：累计成功建造3次=阶段1；累计成功建造9次=阶段2。这是默认建议，必须实现成可修改配置，不可宣称用户已确认。
- 岛上的初始房屋、邮局等建筑建议归类 `landmark`，不占玩家通过专注赢得的额度，也不自动写入契约铭牌。建议将旧“空岛”定义为无玩家成就建筑，而不是完全无地标。
- P0 演示若需要展示三个阶段，用**只读的开发预览模式或独立种子数据**展示，不得绕过“同日最多3次”和“第4次勋章”约束，正式生产构建禁用作弊参数。

### V2-03 相机与缩放
- 阶段0应完整展示小岛，阶段1适度缩远，阶段2自动缩到能看见整岛。
- 阶段2支持：鼠标滚轮 / 双指捏合缩放；触控拖动和鼠标拖动平移；可选 UI 的 `+`、`−` 和“归位”按钮以保证可发现性。
- 缩放以手势中心或指针位置为焦点，有限制边界，避免出现整屏水面或岛屿偏出视野；缩放范围依据实际 UI 安全区测量，可先以 `0.65..1.6` 作为可调整示例，不必强制固定。
- 相机只缩放地图世界层；右下角拉钩按钮、左上返回按钮和右上信息卡等 HUD 不随地图缩放。
- 输入互斥：建造拖动过程中不触发地图平移；双指缩放不误放置道具；点击已建物件时不误触地图拖动。事件坐标统一转换为世界坐标后再转 grid 坐标。

### V2-04 建造与素材库
- 新增素材库内容，目标不少于 **36件可选素材**，按 3 批组织（建议批次为基础12件 / 30分钟12件 / 60分钟12件）；用户已明确希望扩充，但数量36为工程建议，不是最终冻结决策。
- 素材类型应覆盖：树木/花草、房屋建筑、大型地标、公共设施、沙滩道具、岩石场景、小动物。
- 支持不同尺寸的 footprint：示例1x1（花草、动物）、2x2（小树、长椅）、3x3（普通建筑）、4x4（大型地标），最终取决于实际 sprite 和视觉尺寸。
- 植物、建筑和设施都可代表“一次专注获得一次建造机会”；日饱和规则为**每日最多3次有效放置**，不因扩充资源而增加。
- 资源类型与地形允许性映射配置化：草地放大部分通用物件、沙滩道具主要限沙地、岩石景观主要限岩石格；海水禁放。
- 保持建造位置合法性检查（占地、重叠、区域）以及建造后的铭牌和存储。
- 场景应有建设前后明显变化，但不允许一次性把图3所有建筑写死成地图背景：这些图中的建筑大多应是已建存档/演示种子数据带来的可交互物件。

### V2-05 存档迁移与回归测试
- 保留旧存档中的历史 `IslandItem` 坐标、合同引用、今日进度、累计分钟等数据。
- 引入 `mapStage` / `unlockedTileSet` / `mapVersion` 等字段应支持默认值与迁移逻辑；升级后需防止重复授予扩地或覆盖用户地块。
- 若旧世界坐标与新版格子坐标不同，必须定义明确迁移映射并校验合法性，**不得静默丢失或重排用户建造记录**。
- 任何特效、扩展、素材库改造不得影响：拉钩2秒、计时低刺激、暂停超10分钟中断、完成庆祝、`?fast=1`、每日3次、第4次独立勋章及家长周报逻辑。

## 3. UI 与视觉细节
- 画面横版，沿用现有设计比例与UI布局；岛屿地块核心区应更大、海面简洁（减少视觉细节）。
- 保留角色站在左下云朵、右下拉钩按钮、右上岛屿信息卡的叙事结构；角色和UI均是独立图层/资源。
- 岛屿网格是规则的、浅色块交替，避免格子线过粗干扰儿童视觉。
- 图4局部放大截图中，HUD 仍应保持屏幕固定位置与原大小。
- 岛上可展示固定地标，但新建造物件一定要独立 Sprite，不能永久“画死”在背景里。

## 4. 推荐的技术拆分（供 Codex 结合现有代码调整）
- `IslandMapConfig`: 阶段对应的 terrain tile 和合法 footprint 信息。
- `IslandMapRenderer`: 分层渲染海面、tile、岸边、装饰和建筑 sprite。
- `IslandExpansionService`: 累计建造阈值、阶段升级、扩张动画和状态迁移。
- `IslandCameraController`: fit to bounds、zoom、pan、pinch、screen/world mapping、镜头边界。
- `PlacementService`: footprint、地形匹配、越界、重叠、吸附、落点合法性。
- `AssetCatalog`: 分类、批次、资产文件、尺寸、地形限制；与美术 manifest 同步。
- `SaveStore`: schemaVersion、mapStage、tile/unlock 与建筑状态的版本迁移。
- 保持已有的 `Contract/Timer/Progress` 纯逻辑服务不变，除非测试证明须修改。

## 6. 需要最终确认的设计决策（不阻塞先开发地图系统）
- 扩岛阈值：推荐3/9累计建造（可改配置）。
- 36件初始资产规模与各批比例：推荐12/12/12（可改配置）。
- 大型地标是否为玩家消耗一次建造机会放置：暂建议是，且仅在阶段2开放。
- 是否允许玩家手动点击“扩地”或到阈值自动解锁：建议自动解锁并展示短暂的扩张过场。
- 起始建筑是固定公共地标，不计入“今日建造”。
