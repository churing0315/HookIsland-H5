# 《拉钩岛》阶段 1：美术与音频资源清单

> 来源：《拉钩岛美术素材清单与视觉规范》V1.0、产品决策回复、人物设定图及《美术参考.zip》，并按开发依赖重新整理。  
> 状态：规划清单，不代表素材已经制作完成。  
> 源资产格式：每个素材保留独立可编辑源文件；运行时可派生 SVG/PNG/WebP、子集化 WOFF2、mp3/ogg 和图集；程序动画不计入静态文件数。

## 1. 制作原则

- 812×375 横屏为当前设计基准，采用二维分层 + 轻量伪 2.5D、固定正交斜俯视 30–35°；旧版 375×812 场景/UI 规格需要横屏重排；
- 低饱和马卡龙、圆角团子造型、分色平涂、深棕分组描边，禁止纯黑；
- 统一 2.5px 视觉描边，round linecap/linejoin；
- 静态画面禁常驻发光、禁渐变、禁方向投影；落地只允许极淡椭圆软阴影；
- 单画面色相不超过 5 组；当前 Demo 只使用“剩余绿”作为高饱和功能色；勋章金随勋章功能一并移出；
- P4 计时屏只有纯色背景、色盘、角色、任务名和暂停/继续控制；
- 每个建造物包含 4 个交付文件：静态、剪影 `_sil`、生长 `_k1`、生长 `_k2`；
- 文件基名必须与配置中的 `svgKey` 一致，不使用空格、中文文件名或临时版本后缀；
- 项目优先级：**玩法完整性 → 美术效果 → 功能稳定性 → 加载性能优化**；
- 不设置以牺牲画质为代价的统一小包硬上限；采用按需加载、图片/音频压缩、资源复用和浏览器缓存控制体验；
- 所有游戏素材必须保留独立、可修改、可替换的源文件；压缩图、图集、转码音频和字体子集只是运行时派生物，不得覆盖或取代源文件。

## 11. Phaser 资产 Manifest 建议字段

```ts
interface AssetDefinition {
  id: string;
  name: string;
  category: 'scene' | 'mascot' | 'item' | 'icon' | 'ui' | 'fx' | 'audio';
  priority: 'P0' | 'P1' | 'P2';
  unlockBatch?: 1 | 2 | 3;
  svgKey?: string;
  sourceSize?: { width: number; height: number };
  footprint?: Array<{ x: number; y: number }>;
  allowedTerrain?: Array<'grass' | 'water'>;
  variants?: { silhouette?: string; growK1?: string; growK2?: string };
}
```

`footprint` 和 `allowedTerrain` 是原资源文档缺少但建造系统必需的配置，应由美术和关卡共同确认，不要从图片透明边界自动猜测。

## 14. 运行时分组与最终体积报告

### 14.1 按需加载分组

| 分组 | 包含资源 | 加载时机 |
| --- | --- | --- |
| `boot` | 启动标志、最小加载 UI、基础配置 | 首次打开立即加载 |
| `core` | 通用 UI、字体子集、角色基础身份资源 | Boot 后加载并长期复用 |
| `island` | 主岛、海水、角色待机、当前已放物件 | 进入岛屿首页前加载 |
| `focus` | 拉钩、计时、暂停、庆祝所需角色/音频 | 进入任务/计时链路时加载 |
| `build` | 建造抽屉、当前批次物件、生长帧和放置特效 | 契约完成前预取 |
| `report` | 家长周报 UI 与图表资源 | 打开家长入口时加载 |
| `p1-p2` | 后续解锁、分享卡、等级与回归资源 | 功能首次使用时加载 |

同一文件不得复制进多个分组；公共纹理和音频由 `core` 复用。构建文件使用内容哈希，允许静态托管配置长期浏览器缓存；HTML 与资源 manifest 使用短缓存以便版本更新。

### 14.2 源文件与运行时派生物

- 每项资源分配稳定 `assetId`，manifest 同时记录 `sourcePath`、`runtimePath`、格式、尺寸、分组、哈希和审核版本；
- 源文件保持独立图层/路径/关键帧和原始尺寸；不得只交付合并图集、扁平截图或压缩后的最终图；
- 图集和共享部件可以用于运行时优化，但必须能从独立源文件重复生成；
- AI 素材同时保存输入母版、提示版本、原始输出和人工修订文件；
- 音频保存无损或高质量母版，mp3/ogg 仅作运行时编码；字体保存原始 TTF，WOFF2 子集仅作运行时编码。

### 14.3 最终交付体积统计

最终交付必须按 `docs/08-资源体积统计报告模板.md` 生成 Markdown/JSON 两种资源报告，至少包括：

1. 完整构建包磁盘体积与压缩传输体积；
2. 从空缓存打开到岛屿首页可交互的首屏请求清单、实际加载体积和压缩传输体积；
3. 代码/CSS、配置、图片、字体、音频及其他文件的体积、文件数和占比；
4. `boot/core/island/focus/build/report/p1-p2` 各加载组体积；
5. 最大的 20 个运行时文件、重复内容检查和未被引用文件；
6. 与上一批准版本相比的增减量及原因；
7. 浏览器缓存命中验证与二次进入的新增下载量。

报告用于发现异常和指导优化，不得单独作为降低已批准美术品质的理由。
