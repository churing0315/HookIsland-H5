### A04 主视觉与视角

**已确认：**

- 干净二维/弱 2.5D 平涂、圆润暖棕描边、低饱和粉彩、极轻两阶分色；
- 主玩法采用二维分层 + 轻量伪 2.5D，不采用多层悬崖式重透视；
- 固定正交斜俯视 30–35°，无消失点、无近大远小、相机不可旋转；
- 建筑显示正面和少量屋顶；物件以落脚点 Y 值排序；
- 空岛至少保留 45% 视觉留白。

### A05 岛形、水陆和昼夜

**已确认：**

- 首版只做一个主岛，不做多岛切换；
- 草地为主要可建区，水域独立标记；
- 至少提供 60 个可用占用格；
- 夜态只对 World 做轻微冷色合成与少量暖窗，不改变 DOM UI、P4 和角色固有色；
- 不增加月亮、星空、萤火虫、天气或季节系统。

**样张门：**岛屿具体轮廓、60+ 格 mask 和昼/夜色感在 G1/G3 审核。

### A06 水系物件与 footprint

**已确认：**

- 默认 S=1×1、M=2×2、L=3×3；
- 鲸鱼、小鸭、小船仅允许水域；
- 池塘是草地上的 3×3 特殊物件；
- 其余物件在首轮样张后逐项冻结精确 footprint；不得从透明边界自动推断。

## 3. C 组：音频、记录与审核

### C01 音频策略

**已确认：**Demo 以合适的配音及音效保证展示效果为主，当前不把授权作为样片制作阻塞项，后续重新生成。

安全边界：

- 计时和暂停等待期间始终静音；
- 配音只用于关键引导和完成反馈，不连续播报；
- 所有临时音频标记 `demo-placeholder` 并保留来源/用途；
- 临时音频不得进入正式公开发布包；发布前统一重新生成或替换为权利清晰版本。

### C02 生成记录

**已确认保留：**输入参考、提示/版本、生成日期、人工修订、权利说明、审核状态和替换历史。

### C03 审核协作方式

采用以下五道审核门：

1. **G0 规则锁定**：确认角色母版、色板、视角、token 与命名；
2. **G1 风格样张**：只制作横屏空岛、B01 角色待机、小树各 1 张；
3. **G2 小批生产**：每批提交 3–5 个同类素材，状态为 `draft/revise/approved`；
4. **G3 游戏内验收**：在 812×375 横屏和目标真机上检查比例、遮挡、低刺激动效、昼夜及 UI；
5. **G4 发布抽检**：检查来源、生成记录、独立源文件、字体/音频替换、按需加载、缓存、资源体积报告和浏览器兼容。

协作分工：AI 负责方案、制作、一致性检查和变更记录；用户在 G1、关键 G2 批次及 G4 做方向/最终确认。未通过当前审核门，不扩大生产批次。

## 4. 当前剩余发布门

以下事项不阻塞少量样张或内部原型，但会阻塞正式公开发布：

1. 角色公开发布权属证明与最终品牌名称；
2. 方正粗圆简体 Web 嵌入/子集化许可；
3. 所有临时配音和音效的重新生成或权利清晰替换；
4. 单主岛 60+ 格 mask、16 款 P0 精确 footprint 与昼/夜游戏内验收；
5. G0–G4 审核记录完整。

## 5. 已确认的资源交付原则

- 优先级：**玩法完整性 → 美术效果 → 功能稳定性 → 加载性能优化**；
- 采用按需加载、图片/音频压缩、资源复用和浏览器缓存；
- 不再用完整包≤5MB作为硬限制，不以明显降低美术品质换体积；
- 所有素材保留独立、可修改、可替换的源文件，运行时文件可重复生成；
- 最终交付资源体积报告，包含完整包、首屏加载、压缩传输、各类素材/加载组占比、最大文件、版本增量和缓存验证。
