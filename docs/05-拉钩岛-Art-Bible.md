# 《拉钩岛》Art Bible（统一美术规范）

> 版本：V1.2-approved  
> 日期：2026-11-20  
> 状态：主视觉、视角、角色色板、单主岛、水陆规则、夜态与 UI 方向已由用户确认。  
> 本文是后续 AI 生图、人工修图、程序绘制和验收的共同上位约束。

## 1. 视觉目标

一句话方向：**横屏、低刺激、治愈系儿童绘本岛屿；圆润清晰的暖棕描边、低饱和粉彩平涂、固定斜俯视 2.5D、适度两阶分色、干净背景和可自由建造的空间。**

三个体验关键词：

1. **可信赖**：角色稳定、色彩温暖、没有失败或惩罚视觉；
2. **可呼吸**：岛屿有留白，物件彼此可识别，不做高密度奖励轰炸；
3. **看得懂**：儿童一眼分清可点击对象、合法位置、当前任务与主要按钮。

## 2. 参考资料优先级

发生冲突时按以下顺序裁决：

1. **正式设定源**：`角色设定.png`，锁定小伴龙身份、比例、造型和六组主色；
2. **产品体验红线**：PRD 的低刺激计时、一约一放、儿童文案与本地隐私规则；
3. **本 Art Bible**：统一场景、道具、UI、光影和生成方法；
4. **风格参考图**：只提取画风要素，不复制具体角色、建筑或构图；
5. **布局参考图**：只提取信息层级和交互组织，不复制品牌、图标、文字或装饰。

任何外部截图、带作者水印图片、其他游戏画面均不得作为可直接交付素材。

## 3. 正式角色锁定规则

正式设定源：`美术参考/角色设定.png`，SHA-256 `88f9da0fa77cd38c01fefa9a85c90f2cb113420d1adfc6de403b210cab24a0e7`。

### 3.1 不可变身份特征

- 黄色圆润身体和大头小身体比例；
- 红色双簇顶冠；
- 双侧大面积红色鬃毛；
- 顶部左右黄色角/耳状附属结构；
- 深棕大椭圆眼、弧形眉、小鼻口、珊瑚色圆腮红；
- 深棕挂绳与蓝色圆形吊坠，吊坠带白色小高光；
- 浅黄色腹部/足部高光；
- 短红尾，尾端为三瓣状。

禁止：改变顶冠数量、删除吊坠、把鬃毛改成翅膀、加衣服、改物种、写实化五官、改变尾端结构或随动作改变头身比。

### 3.3 正式源的使用方式

- 设定图是**生成约束母版**，不是直接切片的游戏精灵；
- 每次生成小伴龙动作必须同时提供正式设定图和固定角色约束块；
- 首张动作样张通过后建立比例模板，后续动作只允许姿态变化；
- 角色轮廓、比例和六组主色不得为了匹配外部参考而改变；
- 不对设定图本身重绘、扩图或覆盖文字后当作新设定。

## 4. 整体画风

### 4.1 形状语言

- 全元素无锐角；角半径至少为视觉描边宽度的 2 倍；
- 角色 1–2 头身，道具“短、圆、胖”，细长结构适当加粗；
- 植物冠幅采用 3–7 个大色块，不画大量碎叶；
- 建筑只保留 3–5 个强识别结构，不做密集窗框、瓦片和机械细节；
- 物件在 64–160px 显示尺寸下仍要一眼可辨。

主风格锚点来自建筑参考中柔和描边、圆角、低细节的道具图；不采用 3D 高光截图的材质表现。

### 4.2 描边

- 812×375 逻辑画布下，基准视觉描边 2.5px；
- `stroke-linecap: round`、`stroke-linejoin: round`；
- 禁纯黑、双线、虚线装饰和外发光；
- 植物 `#5D6B45`、木作 `#6E5236`、角色 `#602711`、水体 `#4F6B85`、织物 `#8A6B5A`；
- 同一物体只选一组主描边色，内部线可用主描边 70–85% 不透明度。

### 4.3 平涂与材质

- 默认纯平涂 + 同色系两阶分色；
- 禁照片质感、塑料高光、金属镜面、3D 体积光和重环境遮蔽；
- 禁全屏纸张噪点、蜡笔颗粒、明显画布纹理；
- 参考图中的手账纸纹和蜡笔感只用于理解“温暖”，不直接复制；
- 极轻纹理如确有必要，透明度≤4%，且不得在 P4 计时页出现。

### 4.4 光影

- 日间无方向性强光；体积由两阶分色表达；
- 落地关系使用极淡椭圆影 `rgba(93,107,69,0.18)`，高度约物体宽 8%；
- 白色高光面积<2%；
- 静态画面禁常驻光晕和闪光；
- Demo 夜态只允许整体调色和极少量低强度暖窗光；UI 与 P4 不参与昼夜调色。

## 6. 透视、镜头与横屏构图

### 6.1 镜头（已确认）

- 主玩法采用**二维分层 + 轻量伪 2.5D**，不采用多层悬崖式重透视 2.5D；
- 固定正交斜俯视，视觉俯角 30–35°，不使用透视相机；
- 无灭点、无近大远小；上下位置表达远近；
- 同规格物体在任何岛屿位置显示尺寸一致；
- 岛屿、建造网格、物件都使用同一投影规则，禁止混入正侧视贴图。
- 建筑可显示正面与少量屋顶，但不得为表现纵深改变统一比例；
- 相机不可旋转；前后遮挡只使用基于落脚点 Y 值的 depth 排序；
- 岛岸只做一层浅高度关系，不设计多层高悬崖、洞穴式遮挡或大面积前景遮挡。

### 6.2 812×375 页面安全区

- 左右各保留 `max(16px, env(safe-area-inset-*)))`；
- 顶部 HUD 安全带约 56px；
- P1 岛屿主体占画面 65–75%，避免被右上 Demo 工具遮挡；
- P5 底部抽屉高 112–128px，展开时岛屿核心可放区仍完整可见；
- 竖屏只显示旋转设备提示，不重排主游戏界面。

### 6.3 岛屿空间（已确认）

- 岛缘轮廓为 3–5 个宽圆凸部，避免碎裂锯齿；
- 首版只做一个主岛，不做多岛切换；
- 草地、沙滩、水体三层边界清晰；
- 至少提供 60 个可用占用格；草地和水域分开配置；
- 草地为主要可建区，水域独立标记；
- 默认空岛保留 45%以上视觉留白，让成长可被看见；
- 环境散点不占网格，不与可放置物争夺注意力。

参考图中的多岛分层、网格、水陆边界可用于结构理解；不能复制其建筑、角色、广告式闪光和高密度布置。

## 7. 道具与建筑规范

### 7.1 尺度等级

| 等级 | 建议 footprint | 显示规格 | 适用 |
| --- | --- | --- | --- |
| S | 1×1 | 64–96 | 花、石、蘑菇、蝴蝶 |
| M | 2×2 | 96–128 | 小树、兔子、风车、秋千、信箱 |
| L | 3×3 或特定水域 | 128–160 | 大树、小屋、池塘、热气球等 |

每个 footprint 由配置定义，不得从透明边界自动猜测。

### 7.2 细节预算

- S 级：1 个主体 + 最多 2 个装饰点；
- M 级：1 个主体 + 2–4 个识别细节；
- L 级：1 个主轮廓 + 3–5 个识别结构；
- 不使用可读文字、品牌标志、外部作品角色脸或复杂花纹；
- b2/b3 的稀有感只通过体量、轮廓和互动性表达，不靠常驻发光。

### 7.3 水系规则

- 默认尺寸规则：S=1×1、M=2×2、L=3×3；逐款配置可在不破坏等级规则的前提下微调；
- 鲸鱼、小鸭、小船使用 `allowedTerrain: ['water']`；
- 池塘是草地上的 3×3 特殊物件，使用 `allowedTerrain: ['grass']`，自身图形包含水面；
- 鲸鱼、小鸭、小船的描边和阴影遵循水体组，不生成草地底座；池塘按草地特殊物件处理；
- 水花、波纹只做轻微程序动画，循环周期≥6s；
- 不做持续跳跃、喷泉或高亮粒子。

## 8. UI Art Bible

UI 参考图只提供信息组织启发，不直接使用其图标、纸张纹理、文字、按钮和品牌语言。

### 8.1 层级

1. 背景 World；
2. 页面级 DOM UI；
3. 半透明遮罩；
4. 中央主面板；
5. 主操作按钮；
6. DemoTools（仅 Demo 构建）。

### 8.2 组件

- 卡片圆角 16–24px；弹窗圆角 20–28px；
- 主按钮高度≥52px，次按钮≥44px；
- 所有触控命中区≥44×44px；
- 图标使用单主体、暖深色描边和浅底；
- 关闭按钮固定右上，不做旋转或强弹跳；
- 面板同时只保留一个主行动，避免儿童选择过载；
- 文案与数字由 DOM 渲染，不烘焙进图片。

字体使用方正粗圆简体，工程 family 为 `FZCuYuan-M03`。原始 TTF 不进入构建；只加载项目字符子集 WOFF2，并提供 `"PingFang SC", "Microsoft YaHei", sans-serif` 回退。正式发布前必须完成 Web 嵌入/子集化许可检查。

### 8.3 页面对应

- P2 任务页：2×4 任务卡网格 + 一组时长花苞 + 单一确认按钮；
- P4：不使用卡片、装饰边框、背景纹理或奖励图标；
- P5：底部横向素材抽屉，未解锁剪影，不采用参考图的多级左侧分类栏；
- P5-1：中央单物品详情卡，最多三行信息；
- P0-B 周报：左侧指标摘要、右侧任务分布条形图；不做岛屿前后对比；
- 完成/解锁：允许一次性小范围庆祝，不复制外部游戏奖励弹窗的光效和货币表现。

## 9. 动效规范

- 计时页：色盘线性消退 + 角色 4s 呼吸；暂停只允许 6s 睡眠 z；
- 拉钩：2.0s，不可跳过；
- 庆祝：3.0s；
- 生长：1.5s，种子/土堆→主体弹性长出→一次性星点；
- 点击弹跳：0.35s，scale 1→1.08→1；
- 云：60–90s 匀速横穿；海水波纹：10s 位移 8px；
- 同屏循环动效≤2 类；禁止闪烁、脉冲、呼吸光和持续金币雨；
- `prefers-reduced-motion` 降低非玩法位移，不改变色盘计时含义。

## 10. AI 生成约束

### 10.1 生成输入分级

- 角色：必须附正式角色设定；外部风格参考只能影响背景/笔触，不能影响角色身份；
- 场景：附本 Art Bible + 1–2 张指定岛屿结构参考，不混入 UI 截图；
- 道具：附本 Art Bible + 1 张柔和描边道具参考；禁止照抄具体构图；
- UI：以布局线框和 token 为输入，不让模型从外部截图重绘整个界面。

### 10.2 固定负面约束

`no photorealism, no glossy 3D render, no neon, no black outline, no sharp corners, no text, no logo, no watermark, no copied characters, no persistent glow, no dense texture, no extra limbs, no altered mascot crest/mane/pendant/tail`

### 10.3 角色一致性检查

- 将新动作与正面/侧面母版叠加检查头宽、眼距、角距、鬃毛外轮廓和吊坠比例；
- 尺寸偏差目标≤3%，非姿态引起的轮廓偏差≤5%；
- 六个主色按取样 token 校验；
- 每次只生成一个动作状态或一组连续关键帧，不在同一图中混入多套风格；
- 未通过角色检查的稿件不得进入动画补帧或批量变体。

### 10.4 文件交付

- 每个素材独立透明 SVG 或透明 PNG；
- 文件基名与 manifest `svgKey` 一致；
- 建造物四件：静态、`_sil`、`_k1`、`_k2`；
- 不保留生成器水印、背景、提示词文字或边缘脏像素；
- AI 生成结果必须记录输入参考、版本、人工修订和审核状态。

### 10.5 审核协作门

1. **G0 规则锁定**：角色母版、色板、视角和 token 有版本记录；
2. **G1 风格样张**：先审横屏空岛、B01 待机、小树各 1 张；未通过不批量扩展；
3. **G2 小批生产**：每批按同类 3–5 个素材提交，记录 `draft/revise/approved`；
4. **G3 游戏内验收**：用 812×375 真机截图检查比例、遮挡、UI 和低刺激动效；
5. **G4 发布抽检**：核对来源、包体、字体/音频替换状态和全部已批准记录。

用户负责关键视觉方向和最终结果确认；AI 负责提出方案、执行一致性检查、记录变更并在每个审核门等待确认。

### 10.6 美术源文件与运行时优化

- 每个角色状态、场景层、建造物、UI、特效和音频保留独立可编辑源文件；
- 图集、WebP、压缩 PNG、字体子集和转码音频只作运行时派生物，不替代源文件；
- 允许裁切透明留白、清理冗余 SVG 节点、无明显降质压缩和共享公共部件；
- 禁止通过降低角色轮廓精度、改变色板、删除分色、压低必要分辨率或减少已批准动画帧来满足体积目标；
- 优化前后必须在 1×/2× DPR 和游戏实际尺寸并排检查，角色脸部、暖棕描边、透明边缘和低对比色块为重点区域；
- 项目优先级为：玩法完整性 → 美术效果 → 功能稳定性 → 加载性能优化。

## 11. 禁止直接使用的参考内容

- UI 截图中的任何按钮、图标、字体、文字、货币、品牌和角色；
- 带作者账号/水印的插画及其中具体建筑、角色和装饰组合；
- 其他游戏截图/GIF 中的地图、角色、建筑或动画帧；
- 参考图内可识别的鸭屋、海岛商店、农场建筑、游乐设备等完整设计；
- 任何 Windows 激活水印、UID、版本号或测试说明。

参考图只允许被抽象为：圆润程度、密度、层级、相对尺度、镜头俯角、色彩温度和交互组织。
